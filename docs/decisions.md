# Decisions

One SPR (Sparse Priming Representation) line per decision: dense, lossy-but-recoverable
facts for an LLM audience, not prose history. Full rationale stays in Git history
(`git log --all -S <topic>`). New decisions append `- NNN Title — facts` with the next
sequential number. This single log replaces the removed `docs/adr/` and `docs/specs/`
trees; recover their prose from Git history.

- 001 Automations tool error handling — `execute()` handlers wrap work in try/catch and return `fail()` from `lib/tool-result` with recovery details; read-only no-parameter tools return none.
- 002 TruncatedText limitHit — `truncateText` sets optional `limitHit: "bytes" | "lines"` so diagnostics know which limit fired; additive.
- 003 Lifecycle context gate simplification — the Automations context gate needs only `currentWorkspaceLabel` + `pathInside(workspaceRoot)`; the `.automations/workspace.env` `existsSync` check was redundant and removed.
- 004 Overlay guard pattern — overlays guard restricted actions at entry (delete in-progress, move outside backlog/todo) and show an immediate status instead of a confirmation flow that always fails.
- 005 Shared selection marker — `>` is the selected-row marker for every overlay/picker; ASCII-safe, color/bold are secondary only.
- 006 Teams as the reference TUI pattern — new overlays copy the Teams pattern (composable pi-tui, keyboard-only with `esc`, `/` search, `>` marker, width-bounded truncation, no layout-critical emoji/ANSI); no shared UI framework.
- 007 Selection state not color alone — selection is a `>` prefix plus bold content; pickers post-process pi-tui's hardcoded `→` prefix via `selectedText`.
- 008 Browser toggle search mode — dense browsers keep action keys (`f`/`m`/`d`) and toggle search via `/` (`Input` + `fuzzyFilter`); search suppresses actions, empty match prints "No matching teams."
- 009 Reserved command names — extension commands must not exactly match built-in pi command names; `scripts/builtins.json` is the inventory, shared prefixes allowed, exact match wins.
- 010 `/name` is the canonical human identity command — built-in `/name` is the single human-facing identity command; `/alias` removed; the registry name reconciles from the pi session name at heartbeat.
- 011 Command/tool stem parity, not 1:1 — commands and tools share a domain stem (`/kanban` + `kanban_*`) but need not pair; descriptions declare human-UI, model-facing, or both.
- 012 Programmatic naming tool — `set_name`/`get_name` replaced `set_alias`/`get_alias` for model/RPC naming; compatibility wrappers removed; `set_name` may dual-write session + registry for immediate consistency.
- 013 `/name` overrides spawn name with metadata — a new name becomes the active display + registry name; the original survives as immutable `spawn_name`; orchestration routes by stable IDs or `spawn_name`/`role`, never mutable display names.
- 014 Reconciliation alert policy — alert only actionable findings (pending messages, blocked peers, confirmed-stale after a fresh read, silent termination); operationally quiet peers are suppressed.
- 015 Matrix attachment ingestion — pi-matrix ingests media `m.room.message`, downloads allowed `mxc://` through size/MIME gates into a local cache, and carries metadata to `message_read`; never auto-executes; encrypted media deferred.
- 016 Agents overlay direct messaging — the `/agents` detail overlay sends human-authored outbound messages through an injected `AgentMessageSender` port; outbound-only, recipient re-resolved before send, inbound stays on `message_read`.
- 017 Session spooling hook lifecycle — spooling stayed an opt-in POC (explicit gate, source bounded to `~/.pi/agent/sessions`, redacted bounded output, retention caps, no default hook, no unredacted export); pipeline/CLIs/installer removed in the 2026-10 simplification.
- 018 Team run state detail boundary — pi-teams run state/details are an internal session-scoped diagnostic only, never public API, durable store, resume source, or approval input without a promotion ADR; promotion never happened.
- 019 Automations owns recurring scheduling — Kanban stays schedule-free (board/tools/events); Automations owns cron/cadences/policy; no cross-extension imports.
- 021 Team checkpoint/resume design — future resume would use claim-check artifacts, idempotency keys, and fail-closed integrity/lineage/approval; design only, never implemented.
- 022 Panopticon MEMORY.md snapshot boundary — `MEMORY.md` was an advisory, bounded, redacted claim-check artifact, never authoritative for routing/liveness/authorization; prototypes deleted under 054.
- 023 Team approval gate quarantine — approval gates were quarantined internal, default-disabled/unwired; traces were diagnostics, not authorization; removed entirely in the Teams simplification.
- 024 Observability JSONL disposition — team observability JSONL mapping stayed internal/provisional; the mapper was removed with the run-detail simplification.
- 024 Private local IPC mode hardening — Pi-owned IPC paths use `0700` dirs / `0600` files; symlinked registry/maildir/files are rejected via `lstat` metadata before use.
- 025 Runtime control plane consolidation — superseded by 048; ownership stayed split by capability rather than merging runtime control; retained as context only.
- 026 Built-in teams project into user scope — built-in team files project verbatim into `~/.pi/agent/teams` on `session_start`, idempotent/non-destructive; the live user file is source of truth; unavailable pinned models fail loudly.
- 027 Team-run node observability — runs gained `node_started`/`node_heartbeat` events and a separate in-flight node collection; stall detection is read-side only (`>30s` no heartbeat, `>60s` idle); completed nodes keep the original record shape.
- 029 Strengthened team context — forced team sessions injected bounded, secret-redacted context (last 5 turns, 4k chars); draft→panel→final `/team review` stayed a candidate, then `/team` interception was removed and teams run only through `team_run`.
- 030 Automations workspace context policy — discovery prefers the project-local `.pi/automations/workspace` registry; reads use gradual disclosure (summary default, guarded section/full); oversized `CONTEXT.md` is archived then rewritten as SPR-style facts.
- 031 Kanban markdown sync — shipped as regen + move-only ingest through the existing mutators with `board.md.shadow` CAS ordering and strict known-ID parsing; removed when views became read-only; JSON export remains.
- 032 Ephemeral scheduler telemetry — queue-level counters reset on stop and surface only through existing channels (snapshot, status, TUI slot); opt-in `CONTINUATION=1` keeps one bounded run summary per task, no history.
- 033 Deterministic evaluation harness — `tests/evals` runs deterministic fixture-based behavioral evaluations in CI with no live model calls; regression budget is zero — intentional behavior changes edit the versioned fixtures, which is itself the approval.
- 033 Structured tool failure metadata — `fail()` accepts optional `FailureDetails` (`code`, `retryable`, `action`, `schemaVersion`, `truncated`, `correlationId`), additive over the open `Record` details.
- 034 Team speed profiles — one shared `fast | balanced | thorough` profile controls latency/cost; precedence is explicit models/limits > profile > manifest defaults; canonical `maxTokens` maps only at provider payload boundaries; Fast Navigator has zero retries and a bounded timeout.
- 035 Governance / model routing consumer — `automations_governance_resolve` is advisory-only: conservative classification, private input routes to the local fallback chain and never cloud, `escalate: true` when no local model exists; never overrides the user's model.
- 036 Swarm worker-pool orchestration — `/swarm` was a bounded worker-pool POC (WIP ≤ 3, no blind retry, artifact evidence gates, parallel write isolation, TTL ceilings), partially superseded by 040; the entire swarm runtime was retired in 1.2.0.
- 037 Semgrep OSS scan step — `rules/custom/` Semgrep OSS rules (command injection, path traversal, unsafe eval, secret literals) run via `scripts/semgrep-scan.mjs` in the CI security job; static patterns only.
- 038 Automations symlink confinement — `ConfinedStore` binds one trusted root at construction; every method lexically confines targets and rejects symlink components before any file operation; legacy unguarded helpers were deleted.
- 039 Declarative swarm protocol — superseded by 040 before implementation.
- 040 Bounded hierarchical swarm orchestration — root/manager/worker authority with inherited caps, one write-enabled node at a time, and claim-check model eligibility at every spawn; implemented then retired with the swarm runtime in 1.2.0.
- 041 Swarm direct execution and file-goal delivery — proposed removing `/swarm` dry-run and fixing file-bearing goal delivery; never implemented, moot after swarm retirement.
- 042 Scheduled approval resume — approval-gated scheduled deliveries use one run-scoped `requestId`, a terminal idempotent approve/reject/defer lifecycle, run-state written before delivery, and failures recorded `interrupted`; deferred runs resume in place.
- 043 External agent mailbox — `AgentRecord.kind: "external"` plus a durable external manifest outside the volatile registry; maildir branches to the record's durable path; external peers skip pid/stall checks; cleanup is guarded to registry-owned paths.
- 044 Spawn-don't-await scheduled runs — the scheduler enqueues each due run instead of awaiting serially, drains via `flush()`, dedupes per `(task, minute)` with `activeRuns`/`lastRun`, and fires one bounded catchup of the most recent missed minute (≤24h).
- 045 Principal boost lease — original `/boost`: principal-only authority, one global slot, ≤3 human yields, classification before every activation, non-sticky baseline reversion, bounded redacted audit, and `RevertFailed` blocking dispatch; the heavy authority/WAL/audit machinery was consciously dropped by 057.
- 046 Standalone pi-boost extension — Boost moved to its own extension owning `/boost`, lease state, and recovery; normal extension loading is fail-closed; Panopticon owns none of it.
- 047 Shared declarative config discovery — one neutral `lib/declarative-discovery` path primitive (builtin → user settings-roots → project, lexical only, no parsing); each extension parses its own files; `lib` never imports extensions or vice versa.
- 048 Standalone pi-teams public boundary — pi-team-workflows owns team tools/commands/run-state; pi-agent-hub owns registry/messaging/health/UI; both use neutral `lib/` and never import each other's private modules; either installs independently.
- 049 Goal continuous execution and liveness — goals gained `runMode: manual | continuous`, correlated evidence (`runId` + monotonic `milestoneRevision`) invalidating stale completion, steer/resume semantics, and a one-shot watchdog nudge; automatic final completion stays forbidden; manual is the default (amended by 055 for `run`).
- 050 Boost lease/yield unification — Fusion (panel + judge) moved from pi-teams into pi-boost as the prompt-scoped `CognitiveLease`; environmental and cognitive boosts share the lease/yield lifecycle, default-deny agent self-boost, and fixed operator caps.
- 051 Goal session-lineage isolation — each goal is an instance under `.pi/goal/instances/<goalId>` bound by private session entries; goal IDs plus session lineage authorize access; unbound sessions cannot see/mutate/complete siblings; legacy flat state migrates once under a lock.
- 052 Boost defaults to single model, no judge — cognitive leases default to exactly one model dispatch with no judge; fusion stays explicit (`boost.mode: "fusion"` or per-call `panelSize`).
- 053 Daemon protocol extraction — the host daemon and its protocol were retired wholesale at Jim's direction: Agent Hub uses only its file-backed registry and Maildir transport; no daemon mode remains.
- 054 Test-only module disposition — production modules whose importers are only tests (or none) are deleted with no exemptions; the rule lives in `tests/shared/test-quality.test.ts` because knip treats tests as project entries and would mask them.
- 055 `/goal run` defaults to bounded continuous execution — plain `/goal run` starts a 20-turn continuous run (pending plan implicitly approved); `--turns N` is the explicit shorter-run escape; completion stays gated.
- 056 Boost selects from the host registry — Boost production code carries no provider IDs; unconfigured settings plan from host-registry text-capable models (auto = clear selection) and fail closed when none exist; stale explicit selections are never silently substituted.
- 057 Boost is an in-session model lease — `/boost` automates the manual model flip: `pi.setModel()`, restore on `agent_settled`, hard 3-yield cap, 10-minute TTL, visible `RevertFailed` reset-only recovery, and a native-style picker/powerline; the ADR-045 authority/WAL/audit machinery was deliberately not re-added.
- 058 Single-ticket delivery event profile — the JSON ticket-delivery loop stayed evaluation-only, never installed: five-stage profile with manual seed, bounded turns/depth, correlation keys, and reconcile-before-mutate; pi-event-loop was retired in 1.2.0.
- 059 Per-goal driver ownership — confined goal instances plus short filesystem transactions exclude competing drivers: opaque driver tokens + monotonic generations, one revision bump per mutation, send admission recorded before calling the host outside the lock, cancellation invalidates generations, no automatic dead-owner takeover.
- 060 Scheduler slot admission — occurrences claim exclusive token-backed slots on `(taskId, UTC minute)` with lock-held CAS; anything uncertain after admission blocks retry fail-closed; approval is a first-class slot state; no age/PID takeover.
- 061 Extension command surface conventions — one primary command stem per extension with subcommands beneath; shared `lib/toggle-command` for toggles and `lib/pi-settings` for atomic settings-block persistence; concise feature-attributed notification voice; pre-existing names stay as aliases.
- 062 pi-automations rename — `pi-coas` → `pi-automations` in one hard cutover (tools, commands, env, settings keys, directories, tests), project-local default home, `AGENT_HOME` fallback removed; historical documents renamed in place.
- 063 Purpose-based repository boundaries — root README navigates, package READMEs own usage, architecture owns cross-cutting boundaries, completed checklists stay in Git history; benchmarks live out of the shipping tree; file-size/co-change/LCOM metric budgets retired as CI gates in favor of structural boundary, state, and safety checks.
- 064 Extension renames for clarity — `pi-panopticon` → `pi-agent-hub`, `pi-teams` → `pi-team-workflows`; directory/package names changed while tool names, config keys, storage paths, and persisted event identifiers stayed unchanged.
- 065 Decision log replaces ADRs — 2026-10-05: `docs/adr/` (64 records) was compressed into this one SPR line-per-decision log with retained numbering; lossy by design, full prose in Git history; reports/plans/archived session state were removed, the session-spool POC (017) removed, `fitness.yml` retired, and `npm run test:evals` dropped.
- 066 Fleet MCP boundary — `fleet-mcp` is a standalone MCP gateway over Agent Hub's external registrar + Maildir (no Pi extension lifecycle), configured by `FLEET_MCP_CONFIG` JSON with a fixed single principal, stdio default plus loopback bearer HTTP, every tool takes a configured workspace alias (never a path), caller identity comes from auth never arguments, and receipts persist atomically (`0600` state, `0700` dir); deployment/Tailscale provisioning is out of scope. Folded here from the removed `docs/specs/` tree.
- 067 Git-only distribution — one distribution path: Git. Install the umbrella or an individual extension by path or `git:` ref; npm publishing, the tag-triggered publish matrix, and vendor-at-pack staging are removed. Each extension keeps its own `package.json` so individual install stays possible; release is a verified tag, not a registry publish.
- 068 Active-doc link validation — `tests/architecture/docs-hygiene.ts` strips fenced code blocks and fails if a relative link in any tracked Markdown file does not resolve, so broken doc links surface in the fast `npm test` loop instead of review.
